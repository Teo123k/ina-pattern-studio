## Implement

Introduce explicit repository transaction operations for intake and versioned project updates. Insert project before assets; commit project, assets, audit and event result together. Use one checked-out PostgreSQL client per transaction, including migrations. Add a new migration for bot/chat/message identity and payload checksum conflict handling; do not rewrite already-applied migration history. Use uniqueness constraints and optimistic row versions or locking for concurrent writes. Test adapters must implement equivalent semantics. Stage media before DB commit and clean up only proven uncommitted objects; preserve the original error when cleanup fails.

## Acceptance

Run against a disposable PostgreSQL database: simultaneous duplicate deliveries create one project/event set; differing payload under same event key is rejected; rollback leaves no partial rows; simultaneous measurement updates cannot both win; records survive service restart.
